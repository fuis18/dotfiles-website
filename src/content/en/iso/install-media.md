A "next, next" graphical installer is convenient, but it hands you a system you do not know the contents of. Installing by hand, step by step, is what teaches you which pieces make it up and, above all, how to repair it when it fails.

## Live USB

An installed system cannot partition or replace itself while running. In the past you booted from floppy disks and CDs, which were slow, fragile and single-use. The live USB solves that: it boots a complete Linux from a thumb drive, loads it into RAM and leaves the machine's disks free to partition, format and mount without anything using them.

For Arch and CachyOS (see [Distro Base](./distro-base/)) the ISO is generated by `archiso` and a new one is published every month. The procedure is the same for any distro: download, verify and write.

Download the ISO from <https://archlinux.org/download/>, check its signature and write it to the thumb drive with `dd`.

`dd` (which comes from Dataset Destroyer, affectionately named because if you mistype a letter you erase your own hard drive) makes a bit-by-bit, block-by-block copy, so confirm with `lsblk` which one it is before running it.

```bash
gpg --keyserver-options auto-key-retrieve --verify archlinux-x86_64.iso.sig archlinux-x86_64.iso

lsblk
dd bs=4M if=archlinux-x86_64.iso of=/dev/sdX conv=fsync oflag=direct status=progress
```

If you install on a virtual machine, enable UEFI and 3D acceleration in its settings. Once inside the ISO, the order is: check the boot mode, configure the keyboard, connect to the internet and, if needed, refresh the signing keys:

```bash
# Should print 64 if you booted in UEFI
cat /sys/firmware/efi/fw_platform_size

# Keyboard
localectl list-keymaps
loadkeys la-latin1

# Network (wired: checking the connection is enough)
ip link
iwctl
```

For Wi-Fi, inside `iwctl` (the same `iwd` that will be installed in the final system, see [Network](./network/)):

```bash
device list
station wlan0 scan
station wlan0 get-networks
station wlan0 connect "Your_wifi"
exit
```

```bash
ping -c 5 archlinux.org
```

If `pacstrap` later fails with signature errors, it is usually an outdated keyring:

```bash
pacman-key --init
pacman-key --populate archlinux
pacman -Sy archlinux-keyring
```

From here on the disk is partitioned and mounted (see [Mounts](./mounts/)), and only then do you move on to the next step.

## chroot

After `pacstrap`, the new system is already copied to `/mnt`, but it is not booted: you are still inside the live USB, and commands like `passwd`, `systemctl enable` or `mkinitcpio` would act on the live system, not on the disk. `chroot` (change root) solves this by changing what a process sees as `/`: you enter `/mnt` and everything you run acts on the new system, as if you had already booted into it.

The idea is not new: `chroot` appeared in Unix V7 in 1979 and Bill Joy added it to BSD in 1982 precisely to test installations and builds. `arch-chroot` is a wrapper from the `arch-install-scripts` that mounts `/proc`, `/sys` and `/dev` first, which plain `chroot` does not mount, and that is why it is used instead of bare `chroot`.

The flow, with the disks already mounted, is this. First the base is installed (`-K` initializes a fresh pacman keyring in the target system):

```bash
lsblk -f
mount | grep mnt

pacstrap -K /mnt base linux-zen linux-zen-headers linux-firmware
pacstrap /mnt sudo nvim git iwd openresolv knot-resolver less
```

Depending on your processor, also install the microcode (`lscpu` tells you which one you have):

| Intel                       | AMD                       |
| --------------------------- | ------------------------- |
| `pacstrap /mnt intel-ucode` | `pacstrap /mnt amd-ucode` |

If you use Btrfs, also add `btrfs-progs` (see [Mounts](./mounts/)). Then, the console keyboard and `fstab`:

```bash
cat > /mnt/etc/vconsole.conf <<EOF
KEYMAP=la-latin1
XKBLAYOUT=latam
EOF

genfstab -U /mnt > /mnt/etc/fstab
arch-chroot /mnt
```

Once inside the chroot, you configure what makes the system unique. First language, time zone and hostname (adjust `es_PE` and `America/Lima` for your case):

```bash
sed -i 's/^#es_PE.UTF-8/es_PE.UTF-8/;s/^#en_US.UTF-8/en_US.UTF-8/' /etc/locale.gen
locale-gen
echo "LANG=es_PE.UTF-8" > /etc/locale.conf

ln -sf /usr/share/zoneinfo/America/Lima /etc/localtime
hwclock --systohc

echo my-pc > /etc/hostname
cat > /etc/hosts <<EOF
127.0.0.1  localhost
::1        localhost
127.0.0.1  my-pc.localhost my-pc
EOF
```

Then, the root password, your user and `sudo` for the `wheel` group:

```bash
passwd
useradd -m user
passwd user
usermod -aG wheel user
groups user

EDITOR=nvim visudo
# Uncomment: %wheel ALL=(ALL:ALL) ALL
```

Enable the services (`timedatectl set-ntp true` does not work here because it needs `systemd` running, so `systemd-timesyncd` is enabled to sync the time from the first boot; the rest are explained in [Network](./network/)):

```bash
systemctl enable iwd knot-resolver systemd-timesyncd
```

The last step is the bootloader. On UEFI, `systemd-boot` is used, which comes with `systemd`:

```bash
bootctl install

cat > /boot/loader/loader.conf <<EOF
default  arch.conf
timeout  3
console-mode max
editor   no
EOF

# UUID of the root partition (in Mounts' Btrfs scheme it is /dev/sda3)
blkid -s UUID -o value /dev/sda3
```

Create `/boot/loader/entries/arch.conf` with that UUID (adjust `intel-ucode` or `amd-ucode` and remove that line if you do not use microcode). On ext4 the `options` are these; on Btrfs you must add `rootflags=subvol=@`, as explained in [Mounts](./mounts/):

```conf
title   Arch Linux
linux   /vmlinuz-linux-zen
initrd  /intel-ucode.img
initrd  /initramfs-linux-zen.img
options root=UUID=YOUR_UUID rw
```

`bootctl` will warn if `/boot` is readable by all users (because of the random seed it stores). In `/etc/fstab`, set the ESP options to `fmask=0077,dmask=0077`. Then regenerate the initramfs and check:

```bash
mkinitcpio -P
bootctl list
```

On BIOS (without UEFI), GRUB is used instead of `systemd-boot`, with a different partition table (a 2 MB "BIOS boot" partition):

```bash
pacman -S grub
grub-install --target=i386-pc /dev/sda
grub-mkconfig -o /boot/grub/grub.cfg
```

To finish, exit the chroot, unmount and reboot (remove the USB when the machine powers off):

```bash
exit
umount -R /mnt
reboot
```

If something fails and you need to get back in, boot the live USB again, mount the disks as before and repeat `arch-chroot /mnt`: the system does not break by entering and leaving.

| Fact             | Details                                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| Origin           | `chroot`: Unix V7 (1979), added to BSD by Bill Joy on March 18, 1982                                                |
| Tool             | `arch-chroot` and `pacstrap` are part of `arch-install-scripts`                                                     |
| Documentation    | <https://wiki.archlinux.org/title/Chroot> and <https://wiki.archlinux.org/title/Installation_guide>                 |
| Source           | <https://gitlab.archlinux.org/archlinux/arch-install-scripts>                                                       |
| Artix equivalent | `basestrap` instead of `pacstrap` and `artix-chroot` instead of `arch-chroot` (see [Distro Base](./distro-base/)) |

**Installation.** The tools already come on the ISO. On an installed Arch they are obtained with:

```bash
sudo pacman -S arch-install-scripts
```

## tty

Graphical installers require a full graphics stack to already be working (video driver, display server, desktop) and hide what really happens behind buttons. If something in that stack fails, you have nothing to fix it with. The tty (from _teletypewriter_, heir to the old teletypes) is the minimal interface the kernel always offers: text and keyboard, depending on nothing else. That is why it is where you install, and also where you repair.

Linux offers several virtual consoles that you switch to with `Ctrl+Alt+F1` through `F6` (or with `chvt`), and each has its own session. The live USB's is the first one; on the installed system, the consoles are where you go back when a graphical session hangs. From them you can review logs, run `snapper` or fix a configuration without needing a graphical environment.

What is worth knowing to work comfortably:

- **Keyboard:** `loadkeys la-latin1` changes it for the session; to make it permanent, write `KEYMAP=la-latin1` in `/etc/vconsole.conf`.
- **Font:** on high-resolution screens the text comes out tiny; `setfont ter-132b` (Terminus, included in the ISO) enlarges it. To make it stick, add `FONT=ter-132b` to `/etc/vconsole.conf`.
- **Type less and paste more:** on the live USB you can run `passwd` to set a password for root and connect from another machine with `ssh root@IP` (if the service is not active, `systemctl start sshd`), which lets you copy and paste this guide's commands instead of typing them.
- **Everything else starts from the tty:** the greeter (see [Greeter](./greeter/)) and the window manager (see [Window Manager](./window-manager/)) are launched from here.

```bash
# Switch virtual console
chvt 2

# Large font and Latin American keyboard
setfont ter-132b
loadkeys la-latin1

# Persist both on the installed system
cat > /etc/vconsole.conf <<EOF
KEYMAP=la-latin1
FONT=ter-132b
EOF
```

| Fact          | Details                                                                                                                      |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Origin        | Virtual consoles of the Linux kernel, heirs to the teletypes (_teletypewriter_)                                              |
| Tools         | `loadkeys`, `setfont`, `chvt` (`kbd` package) and `agetty` (`util-linux`)                                                    |
| Documentation | <https://wiki.archlinux.org/title/Linux_console> and <https://wiki.archlinux.org/title/Linux_console/Keyboard_configuration> |

**Installation.** `kbd` and the Terminus fonts already come on the ISO. On the installed system, the font is added with:

```bash
pacman -S terminus-font
```
